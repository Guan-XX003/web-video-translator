网页口播中文助手 · Windows x64 便携版

适用：Windows 10/11，Intel / AMD 64 位电脑，建议至少 8 GB 内存。
不适用于 Windows 7/8 或 ARM 原生环境。

一、只需三步
1. 将整个 ZIP 完整解压到固定位置（例如 D:\TikTokAssistant）。勿直接在压缩包里运行。
2. 双击「一键启动.bat」。等待本机模型加载完毕，专用 Chrome 会自动打开，插件自动加载并配对。
3. 在专用 Chrome 内打开任意普通网页视频、播放并取消静音，按 Alt+Shift+Y 打开助手并授权标签页音频。
   也可点击右上角拼图菜单中的「网页口播中文助手」。这个音频授权动作由 Chrome 要求，无法由启动脚本代替。

无需安装 Python，无需下载模型，无需手动加载扩展，无需手动复制配对码。
已内置 Whisper base 多语言模型、Windows Python、推理依赖及 Google 官方 Chrome for Testing。
TikTok 优先提取字幕全文；其他网页使用本机识别，每约 15 秒产生一次识别结果。
支持普通 HTTP / HTTPS 网页，包括可捕获音频的内嵌播放器；并非所有站点均已测试。
仅识别已授权标签页的声音，该页广告或多个播放器也可能被识别。
完整刷新、页面跳转或跨站后需再次按 Alt+Shift+Y 授权；同页切换视频会分开记录。
无法读取内嵌播放器进度时显示录音经过时间，时间戳不能用于跳转。
浏览器内部页、file:// 本地文件不支持；DRM / 受保护视频可能无法捕获音频。
音频识别从当前播放位置开始。需要完整口播，请从头播放一次。

二、日常使用
以后继续双击「一键启动.bat」。使用期间保留服务窗口，按 Ctrl+C 停止本机服务。
窗口关闭后本机识别停止。浏览器可手动关闭。
再次启动会使用同一专用配置，保留该浏览器的登录状态及最近文案。
双击时若服务已就绪，不会重复启动模型，会重新打开专用浏览器。

三、数据与网络
音频仅发送至 127.0.0.1:8765，不会上传到外部识别服务。
本机识别模型已放在 models\faster-whisper-base 中，启动强制离线，不会下载模型。
中文翻译仍通过 Google 在线服务，将原文发送给 Google；视频网页、字幕读取和翻译需要联网。
可在插件设置关闭在线翻译，仅保留原文识别。
识别与翻译可能出错，发布前请校对。

四、专用浏览器说明
此包附带 Google 官方 Chrome for Testing，脚本仅在这个浏览器中自动加载本地插件。
新版普通 Chrome 限制通过命令行加载本地插件，因此不能保证用脚本直接装入日常 Chrome。
不会修改日常 Chrome 的配置、注册表、扩展策略，也不会关闭日常 Chrome。
专用浏览器的数据与配对码位于当前用户的 %LOCALAPPDATA%\TikTokTranscriptZh。
首次可能需要在视频网站中登录；不会自动继承日常 Chrome 的登录和扩展（含代理扩展）。
专用浏览器不会自动更新，请之后使用新版便携包更新。无需关闭安全浏览或浏览器安全功能。

五、故障处理
1. 缺少文件：重新完整解压；不要单独移动启动脚本。
2. 提示缺少 DLL：可运行 support\vc_redist.x64.exe（微软官方离线修复包），完成后重新启动。
   正常启动已使用包内 C++ 运行库，不需要管理员权限。
3. 端口被占用：关闭以前启动的识别服务窗口，再试。
4. 服务可以运行但视频/翻译无法访问：检查 Windows 网络及此专用浏览器的网络设置。
5. 「运行诊断.bat」会检查依赖、加载模型并用包内合成英文语音执行离线识别。结果应包含 bedroom。
6. 启动失败的日志位于 %LOCALAPPDATA%\TikTokTranscriptZh\last-error.log。
7. 如浏览器仍开着但需要更新插件，请关闭这个专用浏览器全部窗口，再双击启动；不用关闭日常 Chrome。
8. 此包从 macOS 组装，已做 Windows 二进制架构/依赖检查、包校验、本机离线模型推理及浏览器自动配对验证。
   尚未在 Windows 实机执行，若运行诊断失败，请提供窗口截图或上述日志。

第三方组件来源和哈希：SOURCES.json；解压文件哈希：SHA256SUMS.json。
各依赖许可证位于 runtime\Lib\site-packages 中相应 dist-info 文件夹，Python 许可证位于 runtime\LICENSE.txt。
测试语音为开发时本机合成英文，不含用户视频音频。
